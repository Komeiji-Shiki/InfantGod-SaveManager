# 幼神 · 多存档管理

为《幼神 Demo》提供独立的多槽、多手动存档点界面，并修复与读档直接相关的直播观众栏、辩论血条和角色面板恢复问题。此项目独立于资料终端、自由交谈、自由弹幕和续玩 Mod。

1.0.1 修复滚动时未选中的存档卡片自行变黑：卡片和槽位切换状态时同步原生主题系统保存的源颜色，避免列表复用控件后又套用第一次渲染时的黑底和白字，同时保留游戏当前调色板。

1.0.2 将游戏内入口和页面标题统一为“存档/读取”，并在点击开始菜单项目后完整收起扩展菜单。

适用版本：Windows x64、Unity 2022.3.46f1 Mono、BepInEx 5.4.23.5。插件安装后直接生效：**主菜单“载入游戏”进入新版载入页；游戏内开始菜单的“存档/读取”打开保存与读取页面。** 原有快速保存保留，原“加载”改名为“快速加载”。

## 存档如何组织

- **左侧是游玩线，也就是存档槽。** 原有三个槽保持原编号及原文件；可以继续新增和重命名，不设置人为的槽数量上限。
- **右侧是独立手动存档点。** 每次“新建存档点”都保存新的原生游戏状态和对话快照，不覆盖其他手动点，也不覆盖 F5 快速存档。
- **每张卡片显示当时的场景缩略图、游戏日期时间、已到达剧情标题、实际显示过的台词、最近选项和备注。** 名称和备注在下方输入；名称留空时使用当前已知剧情标题。
- **来源关系记录实际操作。** 读取某个手动点后继续游玩，再保存时，新点会标注来源；未知来源留空。删除来源点时，后续点仍保留来源名称并标注“已删除”。
- **“切换：快存 / 自动”显示原生记录。** 每日记录、连线前记录与独立手动点分开显示，仍可以自行选择读取。
- **原“加载”改为“快速加载 (F9)”。** 它比较当前槽最近一次成功的快速保存与普通保存，读取两者中更新的一次。原生自动记录不参与这个比较，也不跨槽挑选。当前槽没有可用的普通点或快速保存时，保留原版的自动记录回退流程。

在游戏内读取或删除存档点，需要连续点击同一操作两次确认。新建手动点成功后，所选槽成为此后原生自动存档和快速存档使用的游玩线。创建新槽本身不会切换当前游玩线。

界面沿用原作奶黄色、深灰和橙色，使用直角平面布局与游戏字体。新版页面展开到接近全屏的原生内容区，2K 分辨率下标题约 40px，主要正文约 26–30px，控件随画面比例调整。左右列表使用原生 FairyGUI 滚动列表和滚动条，空间允许时显示三列卡片。卡片内容过长时可悬浮查看全文。

入口直接放在原生菜单中，新增的“存档/读取”复用原游戏保存按钮外观。页面的新增、重命名、保存、读取、删除、返回和筛选操作全部使用原生 `MainMenu/Btn_MainMenu`，保留奶黄底、黑字黑边、橙色悬停及按下状态；内部边框随按钮尺寸同步布局。没有小角落入口，也没有新增快捷键。保留游戏原有 F5/F9，按 Esc 可以关闭保存或载入页面。

## 安装

关闭游戏，将发布 ZIP 解压到任意目录。在解压目录打开 PowerShell，执行：

```powershell
powershell -ExecutionPolicy Bypass -File .\Install-Mod.ps1 -GamePath 'B:\Steam\steamapps\common\幼神 Demo\Build'
```

路径应当指向 `Aistalt.exe` 所在的 `Build` 目录。安装器会安装独立插件目录 `BepInEx\plugins\InfantGodSaveManager`；缺少 BepInEx 5 时安装随包附带的加载器。已有本 Mod 文件先备份，已有共用加载器保留。

这个插件管理实际存档数组，因此不提供运行中热停用开关。更新或卸载后重新启动游戏。

## 卸载与存档保留

关闭游戏后，从同一个安装包执行：

```powershell
powershell -ExecutionPolicy Bypass -File .\Uninstall-Mod.ps1 -GamePath 'B:\Steam\steamapps\common\幼神 Demo\Build'
```

**当前游玩线若是第四槽或之后的新增槽，先在游戏中读取原始前三槽中的一个，再正常退出并卸载。** 原版只有三个槽，卸载脚本会检查当前槽位，并在发现新增槽位仍处于使用状态时停止；不会擅自搬移玩家进度或改选另一个槽。使用自定义存档目录时，额外传入 `-SaveDataPath '实际的SaveData目录'`。

卸载保留全部原有和新增槽文件、独立手动点、缩略图、原生对话快照、安装前备份，以及其他 Mod 使用的 BepInEx 加载器。重新安装后可以再次访问新增槽和手动点。

## 存储位置与原生兼容

所有数据跟随游戏的真实存档位置。槽目录通过原生 `SaveSystem.GetES3Settings()` 与 `ES3Settings.FullPath` 解析，快照通过原生 `RewindService` 读写。

| 内容 | 位置与格式 |
|---|---|
| 原有及新增槽 | 原生 `SaveData/slot_编号.es3` |
| 手动点轻量元数据 | `SaveData/Graywill.SaveManager/槽编号/点ID.json` |
| 手动点缩略图 | 同目录的 `点ID.png` |
| 手动点完整游戏与对话状态 | 原生 `rewind` 目录，使用 `__graywill_manual_槽编号_GUID` 独立名称 |
| 辩论及分支补充状态 | 原生 `SaveData.yarnVariables` 和 `RewindSnapshot.variables` 内的专属 `$Graywill_SaveManager_Runtime_v1` 记录 |

列表直接使用已经加载的 `SaveSlot` 对象及独立轻量元数据，不将每个槽中的全部剧情状态复制到界面模型中。缩略图按可见卡片加载，卡片复用时释放旧图。

存档点包含完整原生快照，磁盘占用会随独立存档点增加；本 Mod 不会自动清理玩家创建的手动点。可以在界面选择不再需要的点并删除。

## 读档修复

1. **直播观众栏不再因为静默恢复控制器而保持隐藏。** 原作清理演出时隐藏观众栏，随后通过 `SetSelectedPage/SetSelectedIndex` 恢复直播状态，未触发观众栏订阅的变化事件。补丁在原生控制器和运行状态恢复完成后，调用原生观众栏绑定、显隐及数值刷新方法。
2. **新存档保存每个辩论角色的当前血量与上限。** 原作只保留共享的 `$Heart` 变量，没有序列化独立 `HPBarState`。补丁同步记录角色、当前血量和上限，等原生角色面板完成恢复后重建心形显示，不调用会把血量重置为满值的 `ShowHPBar`。
3. **加载资源包时同步原生控件类型绑定。** 提前加载 FairyGUI 包时调用对应生成的 `Binder.BindAll`，使直播、对话记录等窗口继续使用正确的原生控件类型。角色面板回收、动画停止、默认状态恢复和子控件布局继续由游戏管理。
4. **清理旧辩论状态。** 读档前移除上次运行留下的独立血条，防止它们影响新读入的存档。
5. **开始菜单增加条目后仍保留退出。** 原生列表达到固定高度时会换到第二列，新增普通保存可能把退出排到被裁切的区域。补丁将开始菜单保持为单列，并根据全部条目调整高度；可与续玩进度条目同时使用。
6. **读档后爱式塔保持左侧，连线角色位于右侧。** 原生主持人与来宾最终都追加到同一个角色列表，NPC 先恢复时可能排在主持人前面。补丁在原生布局前使用真实角色映射，把已绑定的爱式塔面板和角色记录移到首位，保留其他 NPC 的相对次序。这里只调整角色列表，不保存或重放子控件几何，也不替换角色素材。

安装前的旧存档没有每角色血量和上限记录时，无法从单个共享变量可靠补出所有辩论状态。本 Mod 不会虚构血量；安装后新建的手动点、F5 快速存档及原生保存会带上补充记录。已有旧档仍能使用观众栏和面板复用修复。

剧情标题仅匹配当前实际节点的已探索标题，未知节点显示“当前剧情片段”，并使用已实际展示的台词及玩家备注帮助区分。界面不会展开尚未到达的剧情树。

## 本地构建

需要 .NET SDK、Python 和本机安装的游戏。游戏运行库仅作本地编译引用，发布包不包含它们。

```powershell
.\build.ps1 -GamePath 'B:\Steam\steamapps\common\幼神 Demo\Build'
```

首次构建缺少 BepInEx 编译依赖时，`src/plugin/bootstrap.py` 从 BepInEx 官方发布准备固定版本加载器。输出安装目录和 ZIP 到 `dist`。输出目录已有内容时请传入新的 `-OutputPath`，以免把旧文件或玩家数据混入新包。

`data/scene-labels.json` 已随源码提交，正常构建不依赖资料终端项目。可选工具 `tools/build_scene_labels.py` 用于从资料终端重新整理无歧义的已探索标题。

本次插件已完成针对游戏实际程序集的编译。运行时与视觉验证结果以交付说明为准；没有新增测试框架或运行全项目测试。
